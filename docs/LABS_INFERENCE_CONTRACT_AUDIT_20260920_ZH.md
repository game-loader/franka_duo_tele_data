## 已确认：数据集与整块推理解码参考不同

数据集 `labs_fr3_link8_delta14_20260916` 共 122 个 episode、46,502 帧。转换程序定义的是每行 follower 目标相对于同一行实测位姿的偏差：

```text
d[t] = p_desired[t] - p_measured[t]
rotvec[t] = Log(R_desired[t] @ R_measured[t].T)
```

这是目标与实测之间的偏差，不等于下一帧位移 `p[t+1]-p[t]`。

`labs_episode.load_episode()` 回放时使用每行自己的 state，能恢复原始绝对目标。当前 `labs_inference.reconstruct_chunk()` 则把请求时的 state 广播给整个 chunk：

```text
正确还原原数据标签：p_desired[t+k] = p_measured[t+k] + d[t+k]
当前客户端解码：   p_command[k]   = p_measured[t]   + d[t+k]
```

第一行参考相同；后续行一般不同。旋转也存在同样的参考不一致。模型一次根据初始观测预测多个动作，不会自动把训练标签转换为相对初始观测的动作；普通 LeRobot action chunk 取样与归一化也不完成这种坐标转换。

目前 SmolVLA `/info` 明确声明各行相对于各自执行时的实测状态，FastWAM `/health` 声明 `dataset same-row delta_xyz`。未见服务端已将整块转换为初始参考的证据。客户端函数注释 `The server rebases ALL rows ...` 与已查服务元信息不符，不能作为正确性的依据。

此前按用户要求实现的整块初始参考执行与现有训练标签存在这一不一致；整块连续执行本身不要求所有 delta 具有同一参考，必须由训练和执行约定共同决定。

## 用真实标签隔离模型后的复现实验

对每个 episode 从第 0 帧开始切分不重叠的完整 32/50 步窗口，忽略尾部不足一个窗口的帧。使用真实标签，分别按各行自己的 state 和窗口首行 state 解码，比较位置。此项是两种目标解释之间的差异，不是模型预测误差，也不是机器人跟踪误差。

| 窗口 | 左臂全行平均偏差 | 右臂全行平均偏差 | 左臂末行平均偏差 | 右臂末行平均偏差 |
|---|---:|---:|---:|---:|
| 32 步 | 40.46 mm | 34.79 mm | 77.40 mm | 66.62 mm |
| 50 步 | 57.68 mm | 50.56 mm | 107.74 mm | 94.07 mm |

episode 0 的首个 50 步块，末行差异为左臂 81.53 mm、右臂 168.46 mm。即使模型完全预测出数据标签，当前解释也不能恢复原轨迹。

先前 archive 中几毫米的终点误差衡量的是机械臂相对于客户端已经构造出的目标。它不能验证该目标是否具有训练时的含义，也不能证明模型选对了物体。当前证据确认轨迹语义问题，但不能仅凭此认定“抓右侧物体”全部由它造成。

## 归一化、左右顺序与图像核查

- 重算全部帧的 state/action min、max、mean、std，与数据集 `meta/stats.json` 比较：min/max 完全一致，mean/std 最大绝对差小于 `1e-7`。action 转换后统计量已重建。
- 客户端发送原始 state，SmolVLA 使用内部 state34 的前 20 维；FastWAM 使用全部 34 维。客户端未进行 state 归一化或 action 反归一化。
- SmolVLA `/info` 声明 checkpoint MEAN_STD 与一次 inverse MEAN_STD；未取得云端训练、服务源码及 checkpoint 统计量，不能据此证明服务实现无误。
- 转换、状态构造、解码、IK 均按左臂在前、右臂在后。state 为左右各 9D 位姿、两夹爪、左右各 7D 关节角；delta action 为左右各 6D、两夹爪。
- 两端共用 FK 和 rotation6D 工具，顺序为 `R00,R10,R20,R01,R11,R21`，旋转 delta 采用左乘 `Exp(dR) @ R_state`，每臂在自己的 link0 坐标系中、末端为 link8。转换 manifest 中 URDF 哈希与记录中的运行时哈希相同。
- 转换与客户端使用相同的 ROS RGB 解码及 libswscale 直接缩放至 640×480，无水平翻转。抽查 episode 0 的 0/80/160 帧及上次 live chunk0 图像，未见明显左右腕图交换或整体镜像；光照、反光和物体摆放存在变化。此抽查不能替代云端模型张量及相机安装校验。
- 上次 live 第一帧夹爪状态为 `[0,1]`，episode 0 第一帧为 `[1,1]`；返回关节起点不等于恢复夹爪、物体和完整场景。

## 直接用数据集观测请求云端模型

输入 episode 0 的第 0、80、160 帧真实 RGB 图像、原始 state 和数据集 task，分别调用两服务；未经过机器人控制。每个观测每个模型只请求一次。下表为首行预测平移 delta 与数据标签的欧氏距离：

| 模型 | 帧 | 左臂 | 右臂 |
|---|---:|---:|---:|
| FastWAM | 0 | 2.63 mm | 0.52 mm |
| FastWAM | 80 | 1.29 mm | 3.53 mm |
| FastWAM | 160 | 2.11 mm | 1.71 mm |
| SmolVLA | 0 | 3.36 mm | 2.34 mm |
| SmolVLA | 80 | 8.50 mm | 6.53 mm |
| SmolVLA | 160 | 4.96 mm | 21.65 mm |

两服务返回动作量级与标签相符，三帧首行动作的夹爪开闭类别也匹配。没有明显统一倍数错误的迹象，但三帧单次抽样不能证明归一化正确、评价模型整体优劣或判断目标物体识别能力。

查询时 FastWAM 为 2,000 step，SmolVLA 为 40,000 step。云端是否使用本地这份数据、如何划分训练验证、相机增强与预处理如何实现，仍需云端源码及配置核验。

## 其他放大因素与建议

数据为 30 Hz，目前参考执行为 9 Hz。32/50 步对应约 3.56/5.56 秒，之后还要末端收敛及网络推理才获得新观测。减速与长时间开环可能增加分布偏移；对接触相关、实测状态相关的动作偏差，不能假设只改变时长就保持行为。不能靠提高刚度、交换左右臂或随意反转 delta 符号修复语义问题。

要继续使用现有 delta14 checkpoint，应先在反馈闭环中验证每次预测的首行动作，或按照明确的逐行实测状态参考约定执行并重新评估；这不要求每步停下，但需要重新设计当前整块预先 IK 的执行接口。不要直接累计 delta：标签不是相邻帧位移。

若目标是继续预先规划、连续执行整块：

1. 可用已有绝对目标 action20 训练，按绝对位姿解释完整输出块。SmolVLA 的输入 state20 与输出 action20 是不同配置，必须分别声明并配套修改客户端。
2. 若必须保留 action14 和初始参考，训练样本窗口内每个未来绝对目标都应重新相对该窗口初始观测求 delta，再重新训练。滑动窗口会使同一原始帧在不同窗口内有不同 delta，不能通过一次静态逐行 20→14 转换等价完成。

后续云端核验应检查：实际训练数据与 checkpoint 统计量、state20 裁剪位置、action chunk 时间索引、相机键/顺序、RGB 数值范围与 padding、训练增强是否包含未同步变换 action 的水平翻转、输入归一化和输出反归一化是否恰好一次、模型输出是否确实执行训练标签同一语义。
